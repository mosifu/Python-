## 三、示例代码分析

### 3.1 `01_正则表达式入门.py`（57 行）

**功能**：用手机号匹配演示 re.match / re.search / re.findall 三大函数及 Match 对象方法。

**代码结构**：
- 第 6 行：import re
- 第 8-9 行：构造 s1（开头是手机号）/ s2（开头不是手机号）两个对比字符串
- 第 14 行：`pattern_phone = r"1[3-9]\d{9}"`，正则核心模式
- 第 17-31 行：re.match 双字符串对比（s1 匹配 / s2 不匹配），并打印 group/span/start/end
- 第 37-40 行：re.search 在 s2 中找第一个手机号
- 第 46-49 行：re.findall 提取全部手机号
- 第 54 行：`pattern_qq = r"\d{5,11}"` 提取 QQ 号

**亮点**：
- **双字符串对比法**（s1/s2）把"match 只看开头"这个最容易混淆的点用实证讲清楚了——s2 中间明明有手机号但 match 返回 None，正是笔记第 54 行强调的核心差异
- r 原始字符串使用正确（第 14 行），并注释了 `r` 的含义
- 每个函数调用前都有 `if result:` 判空，规避了"search 返回 None 直接 .group() 报 AttributeError"的坑点 7

**不足**：
- 无类型提示（Demo 脚本可接受，但延续了跨阶段模式）
- 第 54 行 `\d{5,11}` 提取"QQ 号"实际会混入手机号数字（注释也写的是"数字(包含QQ)"），命名与实现有轻微偏差

### 3.2 `02_正则表达式语法.py`（31 行）

**功能**：量词、\d、字符集、锚点、\w、分组等语法逐一验证。

**代码结构**：
- 第 9-24 行：16 行语法探索全部以**注释形式**保留（`# print(re.findall(...))`），一行一个语法点
- 第 27-30 行：实际运行的分组演示——`\d{4}-\d{2}-\d{2}`、`(\d+)h:(\d+)m:(\d+)s` 元组返回、`.group(3)`

**亮点**：
- **注释式探索法**是正则学习的正确姿势：每个语法点一行测试、运行后保留结果注释，随时可回来对照，比删掉重写更利于积累
- 分组三连演示完整：不加分组返回完整串 → 加分组返回元组 → search+group(3) 取指定组，正好覆盖了笔记第四章 6 节的全部三个层次

**不足**：
- 语法演示与分组演示混在一个文件里，且大部分处于注释状态，实际执行路径只有最后 4 行，与文件标题"正则表达式语法"的覆盖面相比运行部分偏少
- 第 29 行 `re.findall(r"(\d+)h:(\d+)m:(\d+)s",s2)` 逗号后缺空格（PEP8 小瑕疵）

### 3.3 `03_电影榜单数据清洗版.py`（132 行）

**功能**：4.2 电影爬虫的清洗完善版——在原有 11 字段提取 + CSV 存储基础上，新增 3 个清洗函数净化脏数据，是阶段 4 的收官实战项目。

**代码结构**：
- 第 7-10 行：import re / requests / csv / lxml.html（新增 re）
- 第 13-16 行：常量定义（输出文件改为 `csv_data/movie_list2.csv`）
- 第 19-25 行：`get_movie_year(movie_years: list) -> str` — 年份清洗
- 第 28-34 行：`get_movie_start(movie_starts: list) -> str` — 日期清洗
- 第 37-51 行：`get_movie_times(movie_times: list) -> str` — 时长清洗（分组捕获实战）
- 第 54-86 行：`get_movie_info()` — 详情爬取 + 11 字段（接入清洗函数）
- 第 89-93 行：`save_all_movies()` — CSV 存储
- 第 96-131 行：`main()` — 翻页 + 遍历 + 串联
- 第 130-131 行：`if __name__ == '__main__':` 入口守护

**亮点**：
1. **类型标注回归（今日最大进步）**：三个清洗函数全部带 `list -> str` 类型标注（第 19/28/37 行）。这是 08-22 报告中"恢复类型标注"建议的直接落地，也是跨 3+ 会话缺失后的首次恢复，值得重点肯定
2. **清洗三函数统一套路**：判空保护 → re.search 提取 → group 转字符串 → 兜底空串，三个函数模式完全一致（第 19-51 行），可读性和可维护性极佳
3. **注释质量显著提升**：第 45 行注释详细解释了 `group()` vs `group(1)` 的原理（"search 返回的是match对象会匹配到h,用group()转换为xxh,所有使用group(1)指定第一组"），说明学习者真正理解了分组机制，而非死记 API
4. **边界处理完整**：`get_movie_times` 中 `if not min_res and not hour_res: return ''`（第 47 行）——两个数字都取不到时返回空串，正是笔记六章 4 节亮点 4 记载的设计

6. **`if __name__` 守护保持**（第 130 行），4.2 建立的习惯没有回退

**不足**：
1. **爬虫防御三件套仍未补**：全文件无 User-Agent、无 try/except、无 time.sleep（第 56/103/107 行 requests 调用）。这是 4.2 报告 P0 优先级的两项建议，进入 4.3 后依然未落实——已连续两个 session 被标记
2. **encoding 仍为 `utf-8`**（第 90 行）：笔记六章 5 节再次提醒应改 `utf-8-sig`，Excel 打开中文仍会乱码
3. **类型标注覆盖不完整**：`get_movie_info(movie_info_url)`（第 54 行）、`save_all_movies(all_movies_info)`（第 89 行）、`main()`（第 96 行）三个函数仍无标注——清洗函数有、其余没有，半途而废的痕迹明显
4. **无 docstring**：5 个函数均无 docstring，Stage 3 的习惯回退仍在继续
5. **时长清洗用了两次 search 而非合并分组**：`(\d+)h` + `(\d+)m` 两次独立匹配（第 42-43 行）功能正确，但可用 `(\d+)h(\d+)m` 一次匹配 + 两个 group 完成，代码更紧凑（笔记六章 2 节 ③ 也保留了两次 search 写法，二者皆可，仅作优化提示）
