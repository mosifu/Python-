## 三、示例代码分析

### 3.1 `01_csv入门读写.py`（38 行）

**功能**：演示 CSV 两种读写方式——原始文件操作（注释保留）与 csv 库 DictWriter/DictReader。

**代码结构**：

- 第 22-31 行：DictWriter 写入，4 行人员数据
- 第 34-37 行：DictReader 读取并打印

**亮点**：
- `newline=''` 正确使用（第 25、34 行），说明理解了 Windows 空行问题
- 注释清晰，标注了"方式一/方式二"和每步操作
- 保留了原始方式的注释代码，便于对比两种方法差异

**不足**：
- 使用 `encoding="utf-8"`（第 25、34 行）而非 `utf-8-sig`，笔记第五章 3 节已指出 Excel 打开会乱码
- 无类型提示（延续 Stage 3 以来的模式）
- 列表方式 writer/reader 笔记有讲解但本文件未演示

### 3.2 `02_电影榜单爬取与CSV存储.py`（94 行）

**功能**：完整爬取 TMDB 高分电影榜单，5 页 100 部电影详情，11 字段提取，CSV 批量存储。

**代码结构**：
- 第 11-14 行：常量定义（文件路径 + 3 个 URL）
- 第 17-49 行：`get_movie_info()` — 爬单个电影详情
- 第 52-56 行：`save_all_movies()` — CSV 存储
- 第 59-92 行：`main()` — 翻页 + 遍历 + 串联
- 第 93-94 行：`if __name__ == '__main__':` 入口守护

**亮点**：
1. **`if __name__ == '__main__':` 守护已使用**（第 93 行）——这是此前报告中反复建议的习惯，本次终于落地，值得肯定
2. **空值保护堪称典范**（第 37-48 行）：11 个字段每个都用 `if movie_xxx else ''` 保护，单值字段用 `[0].strip()`，多值字段用 `','.join()`，是爬虫防御性编程的标准写法
3. **轴定位 xpath**（第 30 行）：`contains(text(), 'Director')/preceding-sibling::p[1]/a/text()` 正确使用了 preceding-sibling 轴语法，超出 4.1 笔记覆盖范围
4. **timeout=60 统一设置**（第 19、66、69 行）：所有 requests 调用都设了超时，防卡死
5. **三函数分工清晰**：爬详情 / 存数据 / 主流程职责分离，Java 背景的结构化思维体现明显

**不足**：
1. **无 User-Agent**（第 19、66、69 行）：4.1 笔记已讲过伪装请求头，但本文件所有请求均未加 headers，容易被反爬拒绝
2. **无 try/except**：`get_movie_info` 和 `main` 中的网络请求全无异常处理，单个电影请求失败会导致整个程序崩溃
3. **无 time.sleep**：100 部电影的详情页连续请求，无频率控制，有被封 IP 风险
4. **encoding='utf-8'**（第 53 行）：笔记明确建议用 `utf-8-sig`，代码未改进
5. **'w' 覆盖模式**（第 53 行）：100 部全爬完才写，中途崩溃数据全丢。笔记已指出应用 `"a"` 分批写
6. **POST data 为原始字符串**（第 70 行）：约 400 字符的硬编码字符串，可读性差，应改为字典让 requests 自动编码
7. **无 docstring**：Stage 3 代码所有函数都有 docstring，本文件 3 个函数均无，是习惯回退
8. **PEP8 空行**：第 92-93 行之间缺 2 个空行（函数体结束到 `if __name__` 之间）
