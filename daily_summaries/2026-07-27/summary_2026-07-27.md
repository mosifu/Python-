## 二、类型注解：给代码贴标签（第71-72集）

### 2.1 核心概念

类型注解的定位非常关键：**只是提示，不强制**。笔记中用了"快递贴标签"的类比——标签写"易碎品"，但快递员不一定按标签处理。Python 是动态类型语言，注解写 `int` 照样能赋字符串，运行时不报错；注解真正的价值是给 **IDE 自动补全/错误警告** 和 **mypy 静态检查** 使用。

```python
a1: int = 2
hobby: str = "Python"
flag2: bool = True
d1: None = None          # 注解不改变动态类型的本质
```

### 2.2 容器注解

容器的注解写在方括号里指定元素类型，与 Java 泛型写法高度相似：

```python
names: list[str | int] = ["A", 23, "B"]      # 元素可以是 str 或 int
phones: set[str] = {"123", "234"}            # set[元素类型]
options: dict[str | int, int] = {"count": 2, 555: 10}   # dict[key, value]
goods: tuple[str, int, float] = ("手机", 999, 1.3)      # tuple 按位置写死长度
```

### 2.3 Union 联合类型 `|`

Python 3.10+ 用 `|` 表示"或"（3.10 前用 `typing.Union`）：

```python
x: int | str = 10     # 可以是 int 或 str
x = "hello"           # 合法！
```

这是 Java 没有的直接语法——Java 中通常退化为 `Object` 或方法重载。

### 2.4 函数注解与类型推断

函数注解同时覆盖参数和返回值，`*args` 也可以注解（整体是"元素类型元组"）：

```python
def circle_area_len(r: float) -> tuple[float, float]:
    return round(3.14 * r * r, 1), round(2 * 3.14 * r, 1)

def calc_order_cost(
    *args: tuple[str, float, int],   # 每个商品是 (名称, 单价, 数量)
    coupon: int = 0, score: int = 0, express: float = 0.0
) -> float:
    ...
```

类型推断则相反——解释器能自动推断 `x = 10` 是 int，无需显式声明。两者并不冲突：**能推断就不用写，注解用于"提示读者和工具"**。

### 2.5 实战：订单计算器加注解

把 2.4 的电商订单计算器整体升级为带注解版本，跑通流程：手机 4999x2 + 茶叶 78x5 = 10388，减券 10 -> 10378，减积分 4000//100=40 -> 10338，加运费 9.9 = **10347.9**。旧代码"加注解"本身不改逻辑，这正是注解"非侵入式"的体现。

**Java 对比**：

| Python 注解 | Java 对应 |
|-------------|----------|
| `list[str]` | `List<String>` |
| `dict[str, int]` | `Map<String, Integer>` |
| `tuple[str, int]` | `Record<String, Integer>`（Java 14+） |
| `str \| int` | `Object`（无联合类型） |
| 注解仅提示不强制 | 编译期强制类型检查 |

## 三、模块与包：代码的仓库管理（第73-76集）

### 3.1 什么是模块

模块就是一个 `.py` 文件，装着函数、变量、类，供其他文件导入复用——"工具箱"类比。与 Java 不同，Python 模块**不需要构建配置**（无 pom.xml / module-info.java），文件即模块。

### 3.2 三种导入方式

| 方式 | 语法 | 特点 |
|------|------|------|
| 导入整个模块 | `import random` | 调用需加前缀 `random.randint()` |
| 别名 | `import random as rd` | 缩短名字（Java 无别名机制） |
| 导入功能 | `from random import randint` | 直接用功能名，≈ Java 静态导入 |
| 导入全部 | `from random import *` | 不推荐，易命名冲突 |

### 3.3 自定义模块：`__all__` 与 `__name__`

`my_tools.py` 演示了两个"双下划线魔法变量"的配合：

- **`__all__`**：控制 `from module import *` 能导入哪些名字。示例中 `__all__ = ['PI', 'NAME', 'log_separator1', 'log_separator4']`，所以 `log_separator2()` 即使定义了也无法通过 `import *` 导入（但 `from my_tools import log_separator2` 仍可用——**`__all__` 只管 `*`**）。
- **`__name__`**：直接运行时为 `'__main__'`，被导入时为模块名。`if __name__ == '__main__':` 是 Python 的"入口"约定——测试代码只在直接运行时执行，被导入时不产生副作用。

### 3.4 package 包：`__init__.py`

模块多了就用文件夹组织，**含 `__init__.py` 的文件夹就是包**。`__init__.py` 可以写 `__all__`（控制 `from package import *` 导入哪些模块）、`__version__`、`__author__`。导入路径用点号：

```python
from mypackage import my_math                    # 导入包中的模块
from mypackage.my_math import multiply           # 导入包中模块的功能
```

示例中实际建了 `mypackage/`（含 `my_math.py`、`my_config.py`），验证了包结构。**Java 对比**：`__init__.py` ≈ `module-info.java` 的角色（Python 3.3+ 命名空间包可省略，Java 必须有）。

## 四、类与对象：从函数到图纸（第77-79集）

### 4.1 什么是类和对象

类是"图纸"（设计图），对象是"按图纸造出的实物"。`Car` 类可以造出无数辆车。与 Java 的差异：Python **无 `public/private` 访问修饰符**、`self` 必须显式写、类名用大驼峰。

### 4.2 `__init__` 与 `self`

```python
class Car:
    def __init__(self, color, brand, name, price):
        self.color = color      # self.属性 = 参数
        self.brand = brand
        ...
```

- `__init__` 在创建对象时**自动调用**（严格说是初始化方法，对象创建后才调用，并非 Java 意义上的构造方法）
- `self` 是第一个参数，代表当前对象（≈ Java 的 `this`，但**必须显式写**）
- 创建对象直接 `Car("蓝色", "BMW", "X5", 1000000)`，**无 `new` 关键字**，self 自动传入

### 4.3 实例方法

实例方法第一个参数永远是 `self`，通过它访问实例属性：

```python
def running(self):
    print(f"{self.brand}{self.name}正在高速行驶...")

def total_price(self, discount, rate):
    return discount * self.price + rate * self.price
```

**Java 对比**：

| | Python | Java |
|------|--------|------|
| 构造/初始化 | `__init__` | 与类同名构造方法 |
| 当前对象 | `self`（显式） | `this`（隐式） |
| 创建对象 | `Car(...)` | `new Car(...)` |
| 访问控制 | 无 public/private | public/private/protected |
| 动态加属性 | 支持（`c1.color = "red"`，不推荐） | 不支持 |

## 五、魔法方法与类属性（第80-81集）

### 5.1 三个核心魔法方法

魔法方法是 `__xxx__` 形式的特殊方法，**无需手动调用**，解释器在合适时机自动触发：

| 魔法方法 | 触发时机 | Java 对应 |
|---------|---------|----------|
| `__init__` | 创建对象时 | 构造方法 |
| `__str__` | `print(对象)` 时 | `toString()` |
| `__lt__` | `obj1 < obj2` 时 | `compareTo()` |
| `__eq__` | `obj1 == obj2` 时 | `equals()` |

```python
def __str__(self):                        # 不写时 print 输出 <__main__.Car object at 0x...>
    return f"{self.color} {self.brand} {self.name} {self.price}"

def __lt__(self, other):                  # 按价格比较大小
    return self.price < other.price

def __eq__(self, other):                  # 四个字段全相等才算相等
    return (self.price == other.price and self.color == other.color and ...)
```

示例验证：`print(c1)` 输出友好文本；`c1 == c2`（相同配置）为 True；`c1 > c2` 会经 `__lt__` 取反为 False。**这为后续 list 排序（`sort()` 依赖 `<`）铺平了道路**。

### 5.2 实例属性与类属性

| | 类属性 | 实例属性 |
|------|--------|---------|
| 定义位置 | 类内、方法外 | `__init__` 内 `self.xxx` |
| 共享 | ✅ 所有实例共享 | ❌ 各实例独有 |
| 访问 | `类名.属性` 或 `实例.属性` | `实例.属性` |
| Java 对应 | `static` 静态字段 | 普通字段 |

**查找规则**：`实例.属性` 先找实例属性，找不到再找类属性。因此 `self.wheel = 2` 会创建实例属性并**遮蔽**类属性 `wheel = 4`——`c1.wheel` 是 2，`Car.wheel` 仍是 4，其他实例也不受影响。修改类属性（`Car.wheel = 6`）则所有实例同时变化。示例代码完整演示了这一整套遮蔽行为。

## 七、异常处理：程序的安全气囊（第86-87集）

### 7.1 基本语法

```python
try:
    print(my_name)        # NameError: 变量未定义
except NameError:
    print("系统出现异常,请联系管理人员")
```

### 7.2 多异常捕获 + `as e` + `finally`

```python
try:
    print('ABC'[9])       # IndexError
except NameError as e:
    print(f"名字不存在: {e}")
except IndexError as e:
    print(f"索引错误: {e}")
except Exception as e:    # 兜底：捕获所有其他异常
    print(f"程序出错: {e}")
finally:                  # 无论是否异常都执行
    print("释放资源~")
```

- `as e` 取出异常对象，打印详细信息
- **`except Exception` 兜底**保证不放过任何异常
- `finally` 无论 try 是否异常、是否 return 都会执行，用于释放资源（关文件/连接）

### 7.3 异常的传递

异常沿函数调用链**向上传递**，直到被 `try/except` 捕获：

```
fun3 出错 -> fun2 接收 -> fun1 接收 -> main 的 try 捕获
```

这意味着**只需在最外层调用处加 try/except，不用每层都加**。示例中 `fun1 -> fun2 -> fun3` 三层嵌套，`NameError` 在 fun3 深处产生，最终由 `__main__` 中的 try 捕获。

### 7.4 常见异常类型速查

| 异常类型 | 触发场景 | Java 对应 |
|---------|---------|----------|
| `NameError` | 变量未定义 | 编译错误（Java 编译期检查） |
| `ValueError` | 类型对但值非法（`int("abc")`） | `IllegalArgumentException` |
| `TypeError` | 类型不对（`"a" + 1`） | `ClassCastException` |
| `IndexError` | 索引越界 | `ArrayIndexOutOfBoundsException` |
| `KeyError` | 字典 key 不存在 | `NoSuchElementException` |
| `ZeroDivisionError` | 除以零 | `ArithmeticException` |
| `AttributeError` | 属性/方法不存在 | `NullPointerException` |
| `Exception` | 所有异常的父类 | `Exception` |

### 7.5 最实用的场景：保护用户输入

```python
try:
    choice = input("请输入操作(1-5): ")
    match choice:
        case "1": self.add_cart()
        ...
except ValueError:      # 用户输入字母时 float(input()) 触发
    print("输入数值有误,请重新输入!")
except Exception:       # 兜底，防止未知异常导致系统崩溃
    print("操作有误,请重新输入!")
```

**用户输入是不可控的**——这是异常处理最核心的实战价值，购物车/教务系统案例中已经用上。

## 八、常见坑点与 Python vs Java 对比总结

### 8.1 常见坑点

**类型注解与模块**：
1. 类型注解**不强制**——写了 `x: int` 照样能赋字符串，运行时无报错（只有 mypy 会管）
2. `from module import *` 易命名冲突——多模块同名功能互相覆盖，生产代码不推荐
3. `__all__` 只管 `*`——`from mod import xxx` 不受它限制
4. 忘写 `if __name__ == '__main__':` 守卫——模块被导入时会执行测试代码
5. 相对导入路径与绝对导入路径**不要混用**

**面向对象**：
6. `self` 必须显式写——Java 的 `this` 隐式可用，Python 漏写第一个参数必报错
7. `__init__` 是初始化方法而非构造方法——对象先创建，后初始化
8. 实例属性**遮蔽**类属性——`self.wheel = 2` 不影响 `Car.wheel = 4`
9. `__str__` 必须 `return` 字符串——不能 `print`
10. `update(price=None)` 的 None 模式——避免 0 被误判为"不修改"

**异常处理**：
11. `except` 顺序——具体异常在前，`Exception` 兜底在后，否则具体分支永远走不到
12. 不要裸 `except:`——它会连 Ctrl+C（KeyboardInterrupt）都捕获，用 `except Exception as e:`
13. Python 无 `throws` 声明——Java 必须声明，Python 不需要

### 8.2 Python vs Java 核心差异（收官总表）

| 维度 | Python | Java |
|------|--------|------|
| 类型系统 | 动态 + 可选注解（仅提示） | 静态强类型（编译期强制） |
| 类型标注 | `list[str]` / `dict[k,v]` / `str \| int` | 泛型 `List<String>` / `Map<K,V>`（无联合类型） |
| 模块/包 | `.py` 文件即模块；文件夹 + `__init__.py` | `import` + Maven/Gradle 构建配置 |
| 导入别名 | `import mod as md` 原生支持 | 无别名机制 |
| 类 | 无访问修饰符，`self` 显式 | public/private，`this` 隐式 |
| 对象创建 | `Car(...)` 无 new | `new Car(...)` |
| 初始化 | `__init__`（初始化方法） | 构造方法 |
| 打印/比较 | `__str__`/`__eq__`/`__lt__` | `toString()`/`equals()`/`compareTo()` |
| 类级字段 | 类属性（≈ static，且查找规则为先实例后类） | `static` 字段 |
| 异常捕获 | `try/except/finally`，无 throws | `try/catch/finally`，必须 throws |
| 抛异常 | `raise ValueError("msg")` | `throw new ...` |

**贯穿始终的学习方法论**：函数、OOP 里的 `__lt__`/`__eq__`/类属性，几乎每一个 Python 特性都能在 Java 里找到"对应物"，用对比法学，差异点记得特别牢。

3. **`except` 顺序与兜底**：具体异常在前、Exception 在后的习惯要在写代码时自然形成
4. **包的组织**：`__all__` 在 `__init__.py` 与模块中两种角色的区别
5. **`if __name__ == '__main__':` 守卫**：以后每个可运行脚本都养成写入口的习惯
