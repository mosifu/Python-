## 异常处理

> 📺 **对应课程**：第 86–87 集

### 1. 什么是异常

- **是什么**：异常是程序运行时发生的错误，就像开车遇到路障--不处理就抛锚（崩溃），处理了就能绕过继续走。
- **Java 对比**：
  - 相似点：`try/except/finally` ≈ `try/catch/finally`，`raise` ≈ `throw`
  - 不同点：Python **不必声明 `throws`**；用 `except` 不是 `catch`

### 2. 基本语法

```python
try:
    # 可能出错的代码
    print("------------------------------")
    print(my_name)          # NameError: 变量未定义
    print("------------------------------")
except NameError:
    print("系统出现异常,请联系管理人员")
```

### 3. 多异常捕获 + `as e`

```python
try:
    # print(my_name)        # NameError
    # print(1 / 0)          # ZeroDivisionError
    # print('ABC'[9])       # IndexError
    print('ABC'.hello)      # AttributeError
except NameError as e:
    print(f"名字不存在,异常信息: {e}")
except ZeroDivisionError as e:
    print(f"0不能做被除数,异常信息: {e}")
except IndexError as e:
    print(f"索引错误,异常信息: {e}")
except Exception as e:       # 兜底：捕获所有其他异常
    print(f"程序出错,异常信息: {e}")
finally:                     # 无论是否异常都执行
    print("释放资源~")
```

**Java 对比**：

| | Python | Java |
|------|--------|------|
| 捕获 | `except ExceptionType as e:` | `catch (ExceptionType e)` |
| 兜底 | `except Exception as e:` | `catch (Exception e)` |
| 必执行 | `finally:` | `finally { }` |
| 抛出 | `raise ValueError("msg")` | `throw new ValueError("msg")` |
| 声明 throws | ❌ 不需要 | ✅ 必须 `throws` |

### 4. 异常的传递

异常会沿着函数调用链**向上传递**，直到被 `try/except` 捕获：

```python
def fun1():
    print("fun1...running...")
    fun2()              # 调用 fun2

def fun2():
    print("fun2...running...")
    fun3()              # 调用 fun3

def fun3():
    print("fun3...running...")
    print(my_color)     # ❌ NameError 在这里发生

if __name__ == '__main__':
    try:
        fun1()          # 异常从 fun3 -> fun2 -> fun1 传到这里
    except Exception as e:
        print(f"程序出错,错误信息: {e}")
```

**传递链**：`fun3 出错` -> `fun2 接收` -> `fun1 接收` -> `main 的 try 捕获`

> 💡 这意味着你只需在**最外层调用处**加 try/except，不用每层都加。

### 5. 常见异常类型

| 异常类型 | 触发场景 | Java 对应 |
|---------|---------|----------|
| `NameError` | 变量未定义 | 编译错误（Java 编译期检查） |
| `ValueError` | 类型对但值非法（`int("abc")`） | `IllegalArgumentException` |
| `TypeError` | 类型不对（`"a" + 1`） | `ClassCastException` |
| `IndexError` | 索引越界 | `ArrayIndexOutOfBoundsException` |
| `KeyError` | 字典 key 不存在 | `NoSuchElementException` |
| `ZeroDivisionError` | 除以零 | `ArithmeticException` |
| `AttributeError` | 属性/方法不存在 | `NullPointerException` |
| `Exception` | 所有异常的父类 | `Exception` |

### 6. 实战：在系统中应用异常处理

```python
class ShoppingCart:
    def run(self):
        while True:
            choice = input("请输入操作(1-5): ")
            try:
                match choice:
                    case "1": self.add_cart()
                    case "2": self.update_cart()
                    case "5": break
                    case _:   print("输入数字不在范围内!")
            except ValueError:
                # 用户输入字母时 float(input()) 会触发
                print("输入数值有误,请重新输入!")
            except Exception:
                # 兜底，防止未知异常导致系统崩溃
                print("操作有误,请重新输入!")
```

> 💡 这是异常处理最实用的场景--**用户输入是不可控的**，必须用 try/except 保护，否则程序直接崩溃。

## 常见坑点

1. **`except` 顺序** - 具体异常在前，`Exception` 兜底在后，否则永远走不到具体分支
2. **`as e` 获取信息** - `except ValueError as e:` 中 `e` 是异常对象，可打印详细信息
3. **`finally` 总会执行** - 即使 try 里有 return，finally 也会执行（常用于关闭文件/连接）
4. **Python 无 `throws`** - Java 方法要声明 `throws`，Python 不需要
5. **不要裸 `except:`** - 用 `except Exception as e:` 而不是 `except:`（后者连 Ctrl+C 都捕获）

---

## 小结

1. `try/except/finally`：try 放可能出错的代码，except 捕获处理，finally 总会执行
2. 多异常分别捕获，`Exception` 兜底；`as e` 取异常详细信息
3. 异常会沿调用链向上传递，在最外层捕获即可
4. 用户输入场景必须用异常处理保护，防止程序崩溃
