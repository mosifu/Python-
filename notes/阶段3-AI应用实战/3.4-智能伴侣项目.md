## 一、项目架构

智能伴侣是一个典型的 **Streamlit + DeepSeek API** 应用：

```
┌─────────────┐    HTTP    ┌────────────────┐
│  Streamlit   │ ──────────→ │  DeepSeek API  │
│  前端界面     │ ←────────── │  大模型        │
└─────────────┘   响应      └────────────────┘
     │
     ├── st.session_state：会话记忆（跨重跑保存）
     └── 侧边栏：用户个性化配置
```

**项目文件结构**：
```
第3章/
├── 3.ai_partner_1.py      # v1 基础版（非流式 + "message"/"messages" 记忆 bug）
├── 4.ai_partner_2.py      # v2 流式版（修复 memory key，但新增"流式后忘存 full_response"问题）
├── 5.ai_partner_3.py      # v3 完整版（昵称/性格个性化 + 流式 + 记忆）
├── 8.ai_partner_4.py      # v4 会话管理版（JSON 持久化 + 新建/加载/删除会话）
└── resources/
    ├── logo.png           # 资源文件
    └── sessions/          # 会话存储目录（每个会话一个 .json 文件）
```

## 二、系统提示词动态配置

```python
# 用 % 格式化把昵称和性格动态拼进 system prompt
sys_prompt = """
你叫%s,现在是用户的真实伴侣,请完全代入伴侣角色。
规则:
1.每次只回1条消息
2.禁止任何场景或状态描述性文字
3.匹配用户的语言
4.回复简短,像微信聊天一样
5.有需要的话可以用😜🥰😝等emoji表情
6.用符合伴侣性格的方式对话
7.回复的内容,要充分体现伴侣的性格特征

伴侣性格:
-%s
你必须严格遵守上述规则来回复用户。
"""

# 调用时填充（下面这行只是字典中的一个键值项示意，不能单独运行）
# 实际用法：messages=[{"role": "system", "content": sys_prompt % (昵称, 性格)}, *history]
"content": sys_prompt % (st.session_state.nick_name, st.session_state.nature)
```

> 💡 **这就是提示词工程的实际应用**：通过 `%` 字符串格式化，把用户的昵称和性格设置动态注入 system prompt，让大模型扮演不同角色。`%s` 是占位符，`% (值1, 值2)` 按顺序填充。

## 三、会话记忆

### 1. 初始化 + 展示

```python
# 初始化（key 必须一致！）
if "messages" not in st.session_state:
    st.session_state.messages = []

# 展示历史
for message in st.session_state.messages:
    st.chat_message(message["role"]).write(message["content"])
```

> ⚠️ **关键坑**：初始化检查 `"messages"`，存储也必须 `"messages"`。如果写成 `"message"`（漏了 s），每次重跑都会重新初始化，历史全丢。

### 2. 记录用户输入

```python
st.session_state.messages.append({"role": "user", "content": prompt})
```

### 3. 构建 API 能识别的 history

```python
history = []
for msg in st.session_state.messages:
    # 存储用 "ai"，API 要求 "assistant"，三目运算转换
    role = "assistant" if msg["role"] == "ai" else msg["role"]
    history.append({"role": role, "content": msg["content"]})
```

### 4. 调用 API 时展开传入

```python
response = client.chat.completions.create(
    model="deepseek-v4-flash",
    messages=[
        {"role": "system", "content": sys_prompt % (...)},
        *history,      # 解包：把 history 列表的所有元素展开传入
    ],
    stream=True,
    reasoning_effort="high",
    extra_body={"thinking": {"type": "enabled"}}
)
```

> 💡 `*history` 是**列表解包**——把列表展开成一个个参数。`[A] + [B, C]` 和 `[*A, B, C]` 效果类似，都是把多个消息合并进 messages。

### 5. 流式输出 + 记录 AI 回复

```python
# 流式输出容器
response_msg = st.empty()

# 流式拼接
full_response = ""
for chunk in response:
    if chunk.choices[0].delta.content is not None:
        content = chunk.choices[0].delta.content
        full_response += content
        response_msg.chat_message("ai").write(full_response)
# ⚠️ 说明：在 st.empty() 容器上调用 .chat_message() 是当前版本的可用写法
#    不同 Streamlit 版本行为可能不同，若报错可改为 st.chat_message("ai").write(full_response)

# ⚠️ 关键：流式结束后，把完整回复存回历史！
st.session_state.messages.append({"role": "ai", "content": full_response})
```

> ⚠️ **最容易漏的一步**：流式输出是边生成边返回，完整答案拼在 `full_response` 里。**循环结束后必须把 `full_response` 存回 `st.session_state.messages`**，否则 AI 的回复不会进历史，下次对话 AI 就"失忆"了。

## 五、会话管理（第 113-119 集）

v4 用 JSON 把会话存进 `resources/sessions/` 目录，实现**多会话的新建 / 加载 / 删除**。核心是 4 个函数。

### 1. 保存会话 save_session()

```python
def save_session():
    # 构建会话对象：昵称 + 性格 + 会话标识 + 全部消息
    session_data = {
        "nick_name": st.session_state.nick_name,
        "nature": st.session_state.nature,
        "current_session": st.session_state.current_session,
        "messages": st.session_state.messages,
    }

    # 目录不存在就创建
    if not os.path.exists('./resources/sessions'):
        os.mkdir('./resources/sessions')

    # 以"会话标识.json"为文件名保存
    with open(f'./resources/sessions/{st.session_state.current_session}.json', 'w', encoding="utf-8") as f:
        json.dump(session_data, f, ensure_ascii=False, indent=2)
```

> 💡 每次 AI 回复完都调用一次 `save_session()`（第 245 行），保证对话实时落盘。

### 2. 生成会话标识 load_current_session()

```python
def load_current_session():
    return datetime.now().strftime("%Y-%m-%d_%H-%M-%S")
```

> 💡 用时间戳当会话唯一标识，比如 `2026-08-15_20-30-45`。它同时是 `session_state` 里的会话 ID 和磁盘上的文件名（.json）。

### 3. 加载会话列表 load_sessions()

```python
def load_sessions():
    session_data = []
    if os.path.exists('./resources/sessions'):
        files = os.listdir('./resources/sessions')  # 列出目录里所有文件名
        for file in files:
            if file.endswith(".json"):
                session_data.append(file[:-5])       # 去掉 ".json" 后缀，只要会话名
    return session_data[::-1]                        # 切片反转，最新的排最上面
```

> 💡 `os.listdir()` 拿到的是所有文件名字符串列表；`file[:-5]` 用切片去掉末尾 5 个字符（`.json`）。`[::-1]` 反转列表让最新会话显示在最前。

### 4. 加载指定会话 load_session()

```python
def load_session(session_name):
    try:
        if os.path.exists(f'./resources/sessions/{session_name}.json'):
            with open(f'./resources/sessions/{session_name}.json', 'r', encoding="utf-8") as f:
                session_data = json.load(f)
                st.session_state.nick_name = session_data["nick_name"]
                st.session_state.nature = session_data["nature"]
                st.session_state.current_session = session_name
                st.session_state.messages = session_data["messages"]
                st.rerun()  # 加载完立即重跑，界面立刻刷新
    except Exception:
        st.error("会话加载失败!")
```

> ⚠️ **`st.rerun()` 是关键**：点击按钮后 `session_state` 已经更新，但**当次运行已经结束**，界面不会自动按新状态重画。必须显式 `st.rerun()` 强制整个脚本重跑一次，聊天区和按钮高亮才能一次到位。不加的话就要"点两遍"。

### 5. 删除会话 delete_session()

```python
def delete_session(session_name):
    try:
        if os.path.exists(f'./resources/sessions/{session_name}.json'):
            os.remove(f'./resources/sessions/{session_name}.json')  # 删除文件

            # 如果删的是当前会话，清空消息并生成新会话 ID
            if st.session_state.current_session == session_name:
                st.session_state.messages = []
                st.session_state.current_session = load_current_session()
    except Exception:
        st.error("删除会话失败!")
```

> 💡 `os.remove(路径)` 删除文件。删除当前正在用的会话时，要把 `messages` 清空、重新分配新 ID，否则页面还指着已删的会话。

### 6. 侧边栏 UI：新建 / 加载 / 删除

```python
with st.sidebar:
    # 新建会话
    if st.button("新建会话", width="stretch", icon="✏️"):
        save_session()                                # 1. 先保存当前会话
        if st.session_state.messages:                 # 2. 有对话才新建
            st.session_state.messages = []
            st.session_state.current_session = load_current_session()
            save_session()                            # 3. 新会话立即建文件
            st.rerun()

    # 会话列表：一行两个按钮（加载 + 删除）
    session_list = load_sessions()
    for session in session_list:
        col1, col2 = st.columns([4, 1])  # 按 4:1 分配宽度
        with col1:
            # 加载按钮：当前会话高亮为 primary
            if st.button(session, icon="📝", key=f"load_{session}",
                         type="primary" if st.session_state.current_session == session else "secondary"):
                load_session(session)
                st.rerun()
        with col2:
            # 删除按钮
            if st.button("", icon="❌️", key=f"delete_{session}"):
                delete_session(session)
                st.rerun()
```

> 💡 **技巧**：
> - `st.columns([4, 1])` 把一行按 4:1 分成两列，左边放加载按钮、右边放删除按钮
> - `type="primary" if ... else "secondary"` 三目运算：当前会话高亮（变色），其他会话灰色
> - 每个按钮的 `key` 必须唯一：`f"load_{session}"` / `f"delete_{session}"`，否则 Streamlit 报 key 重复错误

## 常见坑点

1. **`"messages"` vs `"message"`** — key 拼写不一致，历史每次重置
2. **流式后忘存 `full_response`** — AI 回复不进历史，下次失忆
3. **点击按钮后不 `st.rerun()`** — 状态已更新但界面不刷新，要"点两遍"
4. **按钮 `key` 重复** — 列表里多个按钮必须用 `f"load_{session}"` 这种唯一 key
5. **`st.chat_message` 角色名** — 自定义 `"ai"` 能用，但 `"assistant"` 更标准
6. **`*history` 解包** — 忘记解包，messages 变成嵌套列表报错
7. **`%` 格式化 vs f-string** — 本项目用 `%`（课程写法），也可用 f-string
8. **删除当前会话不重置** — 会指向不存在的文件，需清空 messages + 生成新 ID
9. **`os.listdir` 只列文件名** — 拿到的是字符串列表，`.endswith(".json")` 过滤、`[:-5]` 去后缀
