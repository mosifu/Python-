## 一、大模型概述

> 📺 **对应课程**：第 88 集

### 1. 什么是大语言模型（LLM）

- **是什么**：大语言模型就像一位读过全网文字的超级学霸——你问它问题，它能理解你的意图并生成合理的回答。本质是一个巨大的神经网络，通过海量文本训练而来。
- **Java 对比**：≈ 调用一个超级复杂的 API 服务，传入字符串，返回字符串。你不需要知道内部算法，只需要会"调用"。

### 2. 本地部署 vs 云端 API

| | 本地部署（Ollama） | 云端 API（DeepSeek） |
|------|:--:|:--:|
| 运行位置 | 自己电脑 | 云端服务器 |
| 需要网络 | ❌ 断网可用 | ✅ 必须联网 |
| 硬件要求 | 高（显卡/内存） | 低（只需能发 HTTP 请求） |
| 费用 | 免费（用电） | 按 token 计费 |
| 隐私 | ✅ 数据不出本机 | 数据上传到服务商 |
| 速度 | 取决于本地配置 | 取决于网络和服务器 |
| 适用场景 | 开发调试、隐私敏感 | 生产环境、高并发 |

## 二、Ollama 本地部署

> 📺 **对应课程**：第 89–90 集

### 1. 什么是 Ollama

- **是什么**：Ollama 是一个本地大模型运行工具，让你像装软件一样下载和运行 AI 模型。它就是大模型的"应用商店"。
- **Java 对比**：≈ 在本地装一个 Docker 容器，容器里跑着一个 AI 服务，你用 `localhost` 就能访问它。

### 2. 安装 Ollama

```bash
# 访问官网下载安装包
# https://ollama.com/download

# Windows 直接下载 .exe 安装即可
# 安装后打开终端验证
ollama --version
```

### 3. 拉取并运行模型

```bash
# 拉取模型（从 Ollama 仓库下载）
ollama pull deepseek-v4-pro    # 拉取 deepseek 模型
ollama pull qwen2:7b           # 拉取通义千问 7B
ollama pull llama3.2:1b        # 拉取 Llama 3.2（小模型，快速测试）

# 直接运行（如果没拉取，会自动下载）
ollama run deepseek-v4-pro
```

> 💡 `ollama run` 后会进入交互式对话界面，直接输入问题即可，输入 `/bye` 退出。

### 4. Ollama 常用指令


## 三、DeepSeek API 调用

> 📺 **对应课程**：第 91 集

### 1. 什么是 API

- **是什么**：API 就像餐厅的点餐窗口——你把"菜单"（请求）递进去，后厨（服务器）做好"菜"（响应）递出来。你不关心厨房怎么做菜，只关心能不能吃。
- **Java 对比**：≈ 调用一个 `RestTemplate.postForObject(url, request, Response.class)`，Java 要写很多配置，Python 一行 `requests.post()` 搞定。

### 2. API 调用三要素

| 要素 | 说明 | 示例 |
|------|------|------|
| **Endpoint** | API 地址 | `https://api.deepseek.com/v1/chat/completions` |
| **API Key** | 身份认证 | `sk-xxxxxxxxxxxxxxxx`（在官网申请） |
| **请求体** | 输入数据 | `{"model": "...", "messages": [...]}` |

### 3. 申请 API Key

```bash
# 1. 访问 DeepSeek 官网 https://platform.deepseek.com/
# 2. 注册/登录账号
# 3. 进入 API Keys 页面
# 4. 创建新的 API Key（以 sk- 开头）
# 5. 复制保存（关闭后不再显示）
```

### 4. 基础 API 调用

```python
import requests
import json

# 配置
API_KEY = "sk-你的API密钥"       # 替换为你的真实 API Key
ENDPOINT = "https://api.deepseek.com/v1/chat/completions"

# 构造请求头
headers = {
    "Authorization": f"Bearer {API_KEY}",
    "Content-Type": "application/json"
}

# 构造请求体
data = {
    "model": "deepseek-chat",       # 模型名称
    "messages": [
        {"role": "system", "content": "你是一个有用的助手"},  # 系统提示词
        {"role": "user", "content": "你好，用一句话介绍 Python"}  # 用户消息
    ],
    "temperature": 0.7,             # 随机性（0-2，越大越随机）
    "max_tokens": 1024,             # 最大返回 token 数
    "stream": False                 # 是否流式输出
}

# 发送请求
response = requests.post(ENDPOINT, headers=headers, json=data)

# 解析响应
if response.status_code == 200:
    result = response.json()
    # 提取 AI 回复内容
    reply = result["choices"][0]["message"]["content"]
    print(f"AI: {reply}")
else:
    print(f"请求失败: {response.status_code}")
    print(response.text)
```

### 5. 用 OpenAI SDK 调用 DeepSeek（课程实战写法）

> 💡 DeepSeek API 兼容 OpenAI 接口标准，可以直接用 `openai` SDK 调用，比 `requests` 更简洁。

```bash
# 安装 OpenAI SDK
pip install openai
```

```python
import os
from openai import OpenAI

# 创建客户端（DeepSeek 兼容 OpenAI 接口）
# DEEPSEEK_API_KEY 是环境变量名，值就是 DeepSeek 的 API Key
client = OpenAI(
    api_key=os.environ.get('DEEPSEEK_API_KEY'),
    base_url="https://api.deepseek.com"    # 指向 DeepSeek 而非 OpenAI
)

# 调用模型
response = client.chat.completions.create(
    model="deepseek-v4-flash",              # 模型名称
    messages=[
        {"role": "system", "content": "你是一个非常专业的AI助理，叫小兰，每次回答都用甜美的语调"},
        {"role": "user", "content": "你是谁，你能帮我做什么"},
    ],
    stream=False,                            # 是否流式输出
    reasoning_effort="high",                 # 推理强度（low/medium/high）
    extra_body={"thinking": {"type": "enabled"}}  # 开启深度思考模式
)

# 输出结果
print(response.choices[0].message.content)
```

**requests vs OpenAI SDK 对比**：

| | `requests` 库 | `openai` SDK |
|------|:--:|:--:|
| 安装 | 内置 | `pip install openai` |
| 代码量 | 较多（手动拼 headers/json） | 少（封装好了） |
| 错误处理 | 手动判断状态码 | SDK 自动抛异常 |
| 流式输出 | 手动解析 chunk | `for chunk in response` |
| 自动重试 | 手动实现 | SDK 内置 |
| **推荐** | 学习原理用 | **实战开发用** |

**DeepSeek 独有参数**：

| 参数 | 说明 | 取值 |
|------|------|------|
| `reasoning_effort` | 推理强度（思考深度） | `low` / `medium` / `high` |
| `extra_body={"thinking": {"type": "enabled"}}` | 开启深度思考模式 | `enabled` / `disabled` |

> 💡 `thinking` 模式让模型在回答前先"思考"，类似 DeepSeek-R1 的推理能力，回答质量更高但速度更慢。

### 6. 请求参数详解

| 参数 | 类型 | 说明 | 默认值 |
|------|------|------|:----:|
| `model` | str | 模型名称 | 必填 |
| `messages` | list | 消息列表 | 必填 |
| `temperature` | float | 随机性（0=确定，2=疯狂） | 1.0 |
| `max_tokens` | int | 最大返回字数 | 4096 |
| `stream` | bool | 是否流式（逐字返回） | False |
| `top_p` | float | 核采样（替代 temperature） | 1.0 |
| `frequency_penalty` | float | 频率惩罚（-2~2） | 0 |
| `presence_penalty` | float | 存在惩罚（-2~2） | 0 |

### 7. messages 中的角色

```python
messages = [
    {"role": "system",    "content": "系统提示词，设定 AI 的身份和行为规则"},
    {"role": "user",      "content": "用户的问题或指令"},
    {"role": "assistant", "content": "AI 助手的回复"},
]
```

| 角色 | 用途 | Java 类比 |
|------|------|----------|
| `system` | 设定 AI 的身份/规则/限制 | 配置参数 |
| `user` | 用户的提问或指令 | 请求参数 |
| `assistant` | AI 的回复（用于多轮对话的历史记录） | 响应结果 |

## 四、API 调用的错误处理

```python
def call_deepseek(prompt, max_retries=3):
    """调用 DeepSeek API，带重试机制"""
    for attempt in range(max_retries):
        try:
            response = requests.post(
                ENDPOINT,
                headers=headers,
                json={
                    "model": "deepseek-chat",
                    "messages": [{"role": "user", "content": prompt}],
                    "temperature": 0.7,
                    "max_tokens": 1024,
                    "stream": False
                },
                timeout=30  # 30秒超时
            )

            if response.status_code == 200:
                return response.json()["choices"][0]["message"]["content"]
            elif response.status_code == 401:
                return "认证失败：请检查 API Key"
            elif response.status_code == 429:
                if attempt < max_retries - 1:
                    time.sleep(2)  # 限流了，等2秒重试
                    continue
                return "请求过于频繁，请稍后再试"
            else:
                return f"服务器错误: {response.status_code}"

        except requests.exceptions.Timeout:
            if attempt < max_retries - 1:
                time.sleep(2)
                continue
            return "请求超时，请检查网络"
        except requests.exceptions.ConnectionError:
            return "网络连接失败，请检查网络"
        except Exception as e:
            return f"未知错误: {e}"

# 使用
result = call_deepseek("Hello, 你是谁？")
print(result)
```

**常见错误码**：

| 状态码 | 含义 | 解决 |
|:----:|------|------|
| 200 | 成功 | - |
| 401 | API Key 无效 | 检查 Key 是否正确 |
| 429 | 请求限流 | 降低频率或加延时 |
| 500 | 服务器内部错误 | 稍后重试 |
| 503 | 服务暂不可用 | 稍后重试 |

## 五、会话记忆方案详解

### 1. 什么是会话记忆

**核心事实**：大模型 API 本身是**无状态的**——它每次收到请求都当第一次对话，**不记得之前说过什么**。

所以"会话记忆"的本质是：

```
你的代码负责"记"（保存历史消息）
每次请求把历史一起发过去（让 AI 看"聊天记录"）
```

### 2. 最简单的多轮对话

```python
messages = [
    {"role": "system", "content": "你是一个有用的助手"},
]

# 第一轮
messages.append({"role": "user", "content": "1+1等于几？"})
response = requests.post(ENDPOINT, headers=headers,
    json={"model": "deepseek-chat", "messages": messages})
reply = response.json()["choices"][0]["message"]["content"]
messages.append({"role": "assistant", "content": reply})

# 第二轮（AI 看了历史，知道在聊什么）
messages.append({"role": "user", "content": "再加1呢？"})
response = requests.post(ENDPOINT, headers=headers,
    json={"model": "deepseek-chat", "messages": messages})
```

> 💡 **核心**：每次把之前的所有消息都发过去。就像你写邮件时"引用上文"——AI 没有记忆，记忆靠你把历史贴回去。

### 3. 不同记忆方案对比

| 方案 | 原理 | 优点 | 缺点 | 适用场景 |
|------|------|------|------|---------|
| **简单记忆** | 把所有消息都发过去 | 实现简单，信息完整 | token 消耗大，对话越长越贵 | 短对话（<10轮） |
| **滑动窗口** | 只保留最近 N 轮 | 控制 token 成本 | 丢失早期关键信息 | 中长对话 |
| **摘要记忆** | 把早期对话压缩成摘要 | 保留核心信息且省 token | 实现复杂，可能丢失细节 | 超长对话 |
| **向量记忆** | 用向量数据库检索相关历史 | 理论上可无限扩展 | 需要额外基础设施 | 企业级应用 |

### 4. 滑动窗口方案

```python
def chat_with_window(user_input, messages, max_rounds=10):
    """滑动窗口：只保留最近 max_rounds 轮对话，始终保留 system 消息"""
    messages.append({"role": "user", "content": user_input})

    response = requests.post(ENDPOINT, headers=headers,
        json={"model": "deepseek-chat", "messages": messages, ...})
    reply = response.json()["choices"][0]["message"]["content"]
    messages.append({"role": "assistant", "content": reply})

    # 滑动窗口裁剪
    system_msg = messages[0]
    if len(messages) > max_rounds * 2 + 1:
        messages = [system_msg] + messages[-(max_rounds * 2):]

    return reply
```

### 5. 摘要记忆方案

```python
def summarize_and_trim(messages, max_rounds=5):
    """把早期对话压缩成一条摘要"""
    if len(messages) <= max_rounds * 2 + 1:
        return messages

    system = messages[0]
    to_summarize = messages[1: -(max_rounds * 2)]

    # 让 AI 自己总结早期对话
    summary_prompt = f"请总结以下对话的核心信息:\n{to_summarize}"
    summary_response = call_deepseek(summary_prompt)

    return [system, {"role": "system", "content": f"历史摘要: {summary_response}"}
    ] + messages[-(max_rounds * 2):]
```

### 6. 完整的 ChatSession 类

```python
import requests
import json

class ChatSession:
    """带会话记忆的对话类（滑动窗口 + token 计数）"""

    def __init__(self, api_key, system_prompt="你是一个有用的助手", max_history=10):
        self.api_key = api_key
        self.messages = [{"role": "system", "content": system_prompt}]
        self.max_history = max_history
        self.total_tokens = 0
        self.endpoint = "https://api.deepseek.com/v1/chat/completions"

    def send(self, user_input):
        """发送消息，自动记忆上下文"""
        self.messages.append({"role": "user", "content": user_input})

        # 滑动窗口裁剪
        if len(self.messages) > self.max_history * 2 + 1:
            system = self.messages[0]
            self.messages = [system] + self.messages[-(self.max_history * 2):]

        headers = {
            "Authorization": f"Bearer {self.api_key}",
            "Content-Type": "application/json"
        }
        data = {
            "model": "deepseek-chat",
            "messages": self.messages,
            "temperature": 0.7,
            "max_tokens": 1024
        }

        try:
            response = requests.post(self.endpoint, headers=headers,
                                     json=data, timeout=30)
            if response.status_code == 200:
                result = response.json()
                reply = result["choices"][0]["message"]["content"]
                self.total_tokens += result["usage"]["total_tokens"]
                self.messages.append({"role": "assistant", "content": reply})
                return reply, self.total_tokens
            return f"错误: {response.status_code}", self.total_tokens
        except Exception as e:
            return f"错误: {e}", self.total_tokens

    def clear(self):
        """清空历史（保留 system）"""
        self.messages = [self.messages[0]]
        self.total_tokens = 0

    def info(self):
        """查看当前会话状态"""
        return {
            "history_rounds": (len(self.messages) - 1) // 2,
            "total_messages": len(self.messages),
            "total_tokens": self.total_tokens,
        }


# 使用示例
chat = ChatSession(api_key="sk-xxx")
r1, _ = chat.send("1+1等于几？")
r2, _ = chat.send("再加1呢？")
r3, tokens = chat.send("刚才我们聊了什么？")
print(f"消耗总 tokens: {tokens}")
print(f"会话状态: {chat.info()}")
```

## 六、网络基础知识

### 1. IP 地址、域名、端口

| 概念 | 说明 | 类比 |
|------|------|------|
| **IP 地址** | 每台联网电脑的唯一编号。内网 `192.168.x.x`，本机 `127.0.0.1` | 门牌号 |
| **域名** | IP 的人类友好名字，如 `api.deepseek.com` | 张三的家 |
| **DNS** | 自动把域名转成 IP | 查门牌号 |
| **端口** | 服务器上的不同"门"，`443`=HTTPS，`80`=HTTP，`11434`=Ollama | 大楼的不同门 |

```python
# 443 是 HTTPS 默认端口，可省略
"https://api.deepseek.com/v1/chat/completions"

# 11434 不是默认端口，必须写
"http://localhost:11434/api/generate"
```

### 2. URL 组成

```
https://api.deepseek.com:443/v1/chat/completions
│      │                  │    │
│      │                  │    └── 路径（Path）
│      │                  └── 端口（Port）
│      └── 域名（Domain）
└── 协议（Protocol）
```

### 3. OSI 七层 vs TCP/IP 四层

```
OSI 七层                    TCP/IP 四层
┌─────────┐
│ 7 应用层 │ ──→ HTTP/DNS     ┌─────────┐
│ 6 表示层 │ ──→ JSON/SSL      │ 4 应用层 │
│ 5 会话层 │ ──→ Session       │         │
├─────────┤                    ├─────────┤
│ 4 传输层 │ ──→ TCP/UDP      │ 3 传输层 │
├─────────┤                    ├─────────┤
│ 3 网络层 │ ──→ IP/路由器     │ 2 网络层 │
├─────────┤                    ├─────────┤
│ 2 链路层 │ ──→ MAC/交换机    │ 1 网络接 │
│ 1 物理层 │ ──→ 网线/光纤     │   口层   │
└─────────┘                    └─────────┘
```

> **你只关心第7层（应用层，写代码）**，其余6层操作系统和 `requests` 库自动处理。

### 4. HTTP 请求格式

```
POST /v1/chat/completions HTTP/1.1                ← 请求行
Host: api.deepseek.com                             ← 请求头
Authorization: Bearer sk-xxx
Content-Type: application/json
User-Agent: python-requests/2.31.0
Content-Length: 256
                                                    ← 空行
{"model": "deepseek-chat", "messages": [...]}       ← 请求体
```

### 5. 请求头详解

| 请求头 | 作用 | 必写？ |
|--------|------|:----:|
| `Host` | 告诉服务器你要访问哪个网站（虚拟主机区分） | ✅ HTTP/1.1 必须 |
| `Authorization` | 身份认证：`Bearer sk-xxx` | ✅ 调 API 必须 |
| `Content-Type` | 请求体数据格式：`application/json` | ✅ POST 建议写 |
| `User-Agent` | 客户端身份标识 | ❌ 可选 |
| `Content-Length` | 请求体字节数 | ❌ requests 自动算 |

### 6. HTTP 响应格式

```
HTTP/1.1 200 OK                                      ← 状态行
Content-Type: application/json; charset=utf-8          ← 响应头
Date: Thu, 28 Jul 2026 10:00:00 GMT
Server: uvicorn
Transfer-Encoding: chunked

{"id": "chatcmpl-xxx", "choices": [...]}               ← 响应体
```

### 7. 状态码速查

| 状态码 | 含义 | 处理方式 |
|:----:|------|:--:|
| **200** | 成功 | 解析响应体 |
| **400** | 请求格式错误 | 检查参数/JSON格式 |
| **401** | 未认证（Key 无效） | 检查 API Key |
| **429** | 请求太频繁（限流） | 加延时重试 |
| **500** | 服务器内部错误 | 稍后重试 |

## 八、Java vs Python API 调用对比

### Python（用 requests 库）

```python
import requests

response = requests.post(
    "https://api.deepseek.com/v1/chat/completions",
    headers={"Authorization": "Bearer sk-xxx"},
    json={"model": "deepseek-chat", "messages": [{"role": "user", "content": "你好"}]}
)
result = response.json()["choices"][0]["message"]["content"]
```

### Java（用 HttpClient）

```java
import java.net.http.*;
import java.net.URI;

HttpClient client = HttpClient.newHttpClient();
HttpRequest request = HttpRequest.newBuilder()
    .uri(URI.create("https://api.deepseek.com/v1/chat/completions"))
    .header("Authorization", "Bearer sk-xxx")
    .header("Content-Type", "application/json")
    .POST(HttpRequest.BodyPublishers.ofString("{\"model\":\"deepseek-chat\",\"messages\":[{\"role\":\"user\",\"content\":\"你好\"}]}"))
    .build();
HttpResponse<String> response = client.send(request, HttpResponse.BodyHandlers.ofString());
```

| 对比项 | Python | Java |
|--------|--------|------|
| 代码量 | 3 行 | 7+ 行 |
| JSON 处理 | 自动序列化/反序列化 | 需手动构造字符串或 Jackson |
| 可读性 | 高 | 低（Builder 模式冗长） |
| 依赖 | `requests`（内置） | `java.net.http`（Java 11+） |

## 常见坑点

1. **API Key 泄露** — 不要提交到 Git，用环境变量 `os.getenv("DEEPSEEK_API_KEY")`
2. **stream=True 时 response.json() 会报错** — 流式输出返回的是事件流而非 JSON
3. **messages 不传 system 也行** — AI 会使用默认行为，但建议设置以控制输出风格
4. **max_tokens 太小** — 回复会被截断
5. **temperature 太高** — 回复可能胡言乱语；太低则过于确定/无聊
6. **Ollama 本地服务没启动** — 确保运行了 `ollama serve`
7. **端口忘写** — `http://localhost` 默认 80，Ollama 的 11434 不是默认端口，必须写
8. **`Content-Type` 忘设** — 服务器可能返回 415（Unsupported Media Type）
9. **`http` vs `https`** — API 都用 HTTPS（加密），本地开发用 HTTP（localhost）

## 小结

1. **Ollama 本地部署**：下载安装 → `ollama pull 模型名` → `ollama run` 或通过 HTTP API 调用 `localhost:11434`
2. **DeepSeek API**：申请 API Key → `requests.post(url, headers, json)` → 解析 `choices[0].message.content`
3. **会话记忆**：AI 无状态，客户端负责存 messages 历史；用滑动窗口或摘要方案控制 token 成本
4. **网络基础**：调 API 只需关心第7层（应用层），URL 由 `协议://域名:端口/路径` 组成
5. **Apifox**：用后置操作脚本提取响应数据并可视化，让 API 调试体验更友好
