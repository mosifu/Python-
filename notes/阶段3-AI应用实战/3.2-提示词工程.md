## 一、什么是提示词工程

> 📺 **对应课程**：第 99 集

### 1. 什么是 Prompt

- **是什么**：提示词就是你给大模型的"指令"--你说什么，决定了 AI 怎么回答。就像给新同事交代任务，你说得越清楚，他做得越好。
- **Java 对比**：≈ 给方法传参数。参数质量决定返回值质量。`模糊的参数 -> 模糊的返回值`。

### 2. 为什么提示词重要

```
同一个大模型，不同的提示词 -> 截然不同的回答质量

❌ "讲一下 Python"      -> 泛泛而谈，可能几千字
✅ "用3句话向Java开发者介绍Python的核心差异"  -> 精准、简洁、有针对性
```

> 💡 **大模型的能力是固定的，提示词决定了你能激发出多少能力。**

## 二、六步法框架（课程核心）

课程总结的写出好提示词的六个步骤：

| 步骤 | 内容 | 一句话记忆 |
|:--:|------|----------|
| 1 | **给大模型设定角色和能力** | "你是XX专家" |
| 2 | **明确核心请求与任务** | "做什么" |
| 3 | **按步骤拆解复杂任务** | "分几步做" |
| 4 | **指定风格与语气** | "怎么说" |
| 5 | **明确输出格式** | "输出长什么样" |
| 6 | **提供输入输出示例** | "参考这个样子" |

### 1. 设定角色和能力

```
你是一位有10年经验的 Python 技术讲师，擅长用生活化类比解释抽象概念。
```

> 💡 角色设定让 AI "进入状态"--告诉它你是谁，它就会用对应身份的专业知识回答。

### 2. 明确核心请求与任务

```
讲解 Python 装饰器（decorator），包括：
- 装饰器是什么
- 为什么需要装饰器
- 基本语法和执行流程
```

> 💡 核心请求是提示词的心脏--AI 需要知道"到底要我干什么"。

### 3. 按步骤拆解复杂任务

```
请按以下步骤完成：
1. 先分析问题的本质
2. 列出可能的解决方案
3. 对比各方案的优劣
4. 给出推荐方案
```

> 💡 复杂任务不拆解，AI 容易跳步骤、遗漏关键环节。这就是**思维链（Chain of Thought）**。

### 4. 指定风格与语气

```
风格要求：
- 通俗易懂，像跟朋友聊天
- 不要堆砌术语
- 适当用类比帮助理解
```

### 5. 明确输出格式

```
输出格式：
- 用 Markdown 表格对比
- 每个概念用 ### 三级标题
- 代码块标注语言类型
```

> 💡 明确格式让输出**可直接使用**，不用二次整理。

### 6. 提供输入输出示例（Few-shot）

```
示例：
输入：[1, 2, 3, 4]
输出：[2, 4, 6, 8]（每个元素乘以2）

输入：["a", "b"]
输出：["aa", "bb"]（每个元素重复一次）

现在请处理：[10, 20, 30]
```

> 💡 给 AI 看几个"样题答案"，它就能举一反三。这叫 **Few-shot Learning**。

## 三、补充四维度（六步法之外）

六步法覆盖了主体，但还有4个重要维度：

### 7. 约束与限制（Constraints）

```
约束：
- 不要编造数据，不确定时说"我不确定"
- 回答不超过200字
- 不要使用"首先""其次"等套话
- 只使用提供的资料，不要引入外部信息
```

> 💡 **告诉 AI 不能做什么，和告诉它能做什么一样重要。**

### 8. 上下文/背景信息（Context）

```
背景：
- 目标用户是 Java 转 Python 的初学者
- 用户已完成 Python 基础语法学习
- 当前在学习 API 调用
```

> 💡 给 AI 足够的背景，它才能给出**贴合你实际情况**的回答。

### 9. 思维链引导（Chain of Thought）

```
请按以下方式思考：
1. 先分析用户的问题本质
2. 列出可能的解决方案
3. 对比各方案的优劣
4. 给出推荐方案并说明理由
```

> 💡 对于复杂问题，让 AI"先想后答"比直接要答案质量高得多。

### 10. 迭代与反馈机制

```
如果你不确定我的需求，请先提问确认，不要直接假设。
回答后请询问："这个回答是否解决了你的问题？"
```

## 五、优化前 vs 优化后对比

### 示例1：学习助手

**❌ 优化前（模糊）**：
```
帮我讲一下 Python 的装饰器
```

**✅ 优化后**：
```
【角色】
你是一位有10年经验的 Python 技术讲师，擅长用生活化类比解释抽象概念。
你的学员有 Java 基础，正在学习 Python 进阶。

【任务】
讲解 Python 装饰器（decorator），包括：
1. 装饰器是什么（用一个生活类比）
2. 为什么需要装饰器（解决什么问题）
3. 基本语法和执行流程
4. 一个实际应用场景（如计时器、日志）

【要求】
- 每个概念都用 Java 对比（如 Java 注解 @Override）
- 代码示例可直接运行，附中文注释
- 输出格式：分4个小节，每节有标题
- 风格：通俗易懂，不要堆术语
- 约束：不要超过800字，不要讲带参数的装饰器
```

| | 优化前 | 优化后 |
|------|--------|--------|
| Java 背景 | ❌ | ✅ |
| 结构 | ❌ 一大段 | ✅ 4小节 |
| 篇幅控制 | ❌ | ✅ 800字内 |
| 深度控制 | ❌ | ✅ 不讲带参装饰器 |

### 示例2：代码审查

**❌ 优化前**：
```
帮我看看这段代码有没有问题
[代码]
```

**✅ 优化后**：
```
【角色】你是一位严谨的 Python 代码审查员，熟悉 PEP 8 规范。

【任务】审查以下代码，检查：
1. 语法错误（能否运行）
2. 逻辑错误（边界情况、潜在 bug）
3. 代码规范（PEP 8、命名、注释）
4. 性能问题

【要求】
- 输出格式：✅/❌ 问题描述 -> 修正建议（附代码）
- 按严重程度排序：致命 > 警告 > 建议
- 只指出问题，不要重写整段代码
- 如果代码没问题，明确说"代码质量良好"

【约束】
- 不要修改原始代码风格
- 不要建议引入尚未学习的高级特性

【代码】
[附上代码]
```

### 示例4：多步骤拆解（思维链）

**❌ 优化前**：
```
我有个购物车系统，怎么加满减优惠功能？
```

**✅ 优化后**：
```
【角色】你是 Python 后端架构师。

【背景】
用户有一个基于 dict 的购物车系统：
shop = {"商品名": {"price": 单价, "num": 数量}}

【任务】
为购物车添加满减优惠功能，请按以下步骤思考：

第一步：分析需求
- 满减规则是什么
- 优惠作用于总额还是单品

第二步：设计方案
- 列出2种方案，对比优劣

第三步：给出推荐方案代码
- 附中文注释，考虑边界情况

【要求】
- 每步先输出思考过程，再输出结论
- 代码只使用 Python 标准库
- 最后给出调用示例
```

## 六、提示词工程速查表

| 技巧 | 一句话 | 什么时候用 |
|------|--------|-----------|
| **角色设定** | "你是XX专家" | 每次都写 |
| **背景信息** | "用户是Java背景" | 需要个性化时 |
| **任务拆解** | "分3步完成" | 复杂任务 |
| **输出格式** | "用表格输出" | 需要结构化时 |
| **Few-shot 示例** | "参考这个例子" | 需要特定风格时 |
| **约束限制** | "不超过200字" | 需要控制输出时 |
| **思维链** | "先分析再回答" | 推理/分析类任务 |
| **否定指令** | "不要用XX" | 防止不良输出 |
| **迭代反馈** | "不确定就问我" | 需求模糊时 |

## 常见坑点

1. **提示词太模糊** - "讲一下 Python" 不如 "用3句话介绍 Python 与 Java 的3个核心差异"
2. **没有约束** - 不限制篇幅/深度，AI 可能输出几千字
3. **不给示例** - 复杂格式要求不给 Few-shot，AI 可能理解偏差
4. **角色太宽泛** - "你是AI助手" 不如 "你是有10年经验的 Python 讲师"
5. **一次问太多** - 一个提示词塞5个问题，不如拆成5次对话
6. **不指定格式** - 不说"用表格"，AI 可能用纯文本段落

---

## 小结

1. **六步法**：角色 -> 任务 -> 拆解 -> 风格 -> 格式 -> 示例，是写好提示词的核心骨架
2. **补充四维度**：约束限制、背景上下文、思维链、迭代反馈，让提示词更完整
3. **核心心法**：把 AI 当成一个聪明但需要明确指令的新同事--你说得越具体，它做得越好
